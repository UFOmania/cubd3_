AddressSanitizer Crash Report

Summary:
The program crashes with a segmentation fault (SEGV) during a free() call inside the free_game_mg() function. The invalid memory access occurs because the program attempts to free a pointer that is either:
- Already freed (double free),
- Never allocated dynamically,
- Or corrupted due to memory overwrites.

Cause:
- Inconsistent memory ownership: some strings (texture paths, map lines) are assigned directly from input buffers without duplicating them, leading to invalid frees.
- Early exit on duplicate entries (e.g., duplicate texture paths) without freeing previously allocated resources.
- As a result, free_game_mg() frees invalid or previously freed pointers causing the crash.

Example of duplicated values triggering the issue:
NO ./path_to_the_north_texture
SO ./path_to_the_south_texture
WE ./path_to_the_west_texture
WE ./path_to_the_east_texture   <-- duplicated "WE" entry
F 220,100,0
C 225,30,0

Sample map lines following the configuration:

1000000000110000000000001
1011000001110000000000001
1001000000000000000000001
111111111011000001110000000000001
100000000011000001110111111111111
11110111111111011100000010001
11110111111111011101010010001
11000000110101011100000010001
10000000000000001100000010001
10000000000000001101010010001
11000001110101011111011110N0111
11110111 1110101 101111010001
11111111 1111111 111111111111

Impact:
- Program aborts with memory errors.
- Undefined behavior and potential data corruption.
- Makes debugging difficult without full cleanup.

Resolution (to be fixed later):
- Always duplicate all stored strings to ensure ownership (e.g., use strdup).
- Implement full cleanup of allocated memory on every error or early return.
- Maintain a consistent memory ownership and freeing strategy.
- Use AddressSanitizer regularly to detect such errors early.

Note:
This report documents the issue for later fixing and does not include an immediate solution.
